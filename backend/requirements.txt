# JWT: PyJWT, NOT python-jose. python-jose was REPLACED (2026-08-20) because it
# declares `ecdsa` as an unconditional core dependency, and ecdsa 0.19.2 carries
# CVE-2024-23342 (HIGH — Minerva timing attack on P-256) for which NO FIX WILL
# EVER EXIST: the maintainers consider side-channel resistance out of scope for
# a pure-Python implementation. No pin could clear it, so the library had to go.
#
# PyJWT has ZERO required dependencies (cryptography sits behind a [crypto]
# extra we do not request) and no ecdsa anywhere, so this removes the finding
# from SCA scans structurally rather than suppressing it. Every JWT on this
# platform is HS256 — symmetric, stdlib hmac — so no asymmetric backend is

# the first release that queries CLEAN, so it was pointless to migrate onto a
# version that reintroduced worse findings than the one being removed.
#
# API divergence handled: python-jose's `jwt.get_unverified_claims(token)` has
# no PyJWT equivalent; it is spelled `jwt.decode(token,
# options={"verify_signature": False})`. One call site,
# app/a2a_common/sdk_hmac_middleware.py. Everything else is source-compatible:
# encode/decode signatures match, every decode already passes
# algorithms=["HS256"], and `JWTError` becomes `PyJWTError`.
